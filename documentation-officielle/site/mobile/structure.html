9. Application mobile

Stack et structure

L'application mobile est l'interface citoyenne de BlockLucky sur iOS et Android. Elle couvre le parcours du citoyen : création de compte et connexion, vérification d'âge, achat et cadeau du ticket du grand tirage, salle d'attente et tirage en direct, tickets à gratter et boutique des commerçants, parrainage, profil, sécurité et RGPD. Elle n'a ni dashboard Mairie ni espace partenaire, qui n'existent que sur le frontend web. Comme le web, elle ne gère aucune clé : le portefeuille de chaque citoyen est créé et utilisé par le backend (voir Portefeuilles intégrés).

Le code se trouve dans mobile-app/. Il est écrit en TypeScript avec Expo et React Native. L'interface suit la maquette Figma de l'application : police Inter, palette jaune « soleil » et encre bleu nuit, cartes arrondies et icônes SVG (voir Thème et composants).

#Dépendances installées mais inutilisées

Plusieurs paquets figurent dans package.json sans être importés dans src/ :

Paquet Situation
axios api.client.ts crée un client axios avec des nouvelles tentatives, mais seul API_BASE_URL est importé ailleurs ; toutes les requêtes passent par fetch via RTK Query (voir Résilience réseau)
expo-notifications Aucun import : pas de notification push native (voir Temps réel et notifications)
expo-crypto Aucun import
lottie-react-native Aucun import ; les trois animations de assets/animations ne sont pas affichées, la roue du tirage est animée avec Animated de React Native
react-native-gesture-handler Aucun import ; la carte à gratter utilise PanResponder de React Native

Ces dépendances alourdissent le binaire sans rien apporter. Elles sont à retirer ou à brancher. Les fichiers assets/fonts/Inter-*.ttf ne sont plus lus non plus : la police vient du paquet @expo-google-fonts/inter.

#Point d'entrée

package.json déclare "main": "src/App.tsx". mobile-app/src/App.tsx appelle registerRootComponent(App). Avant tout rendu, App charge cinq graisses d'Inter avec useFonts (Inter_400Regular, Inter_500Medium, Inter_600SemiBold, Inter_700Bold, Inter_700Bold_Italic). Tant qu'elles ne sont pas prêtes, il affiche une vue vide de couleur #F6F7FA. Il monte ensuite, dans cet ordre :

  1. le Provider Redux avec le store unique de store/index.ts ;
  2. SafeAreaProvider ;
  3. ThemeProvider (thème, langue, dimensions d'écran) ;
  4. AppShell, qui choisit le style de la barre d'état selon le thème et rend RootNavigator.

Au montage, App appelle sentryClient.init(). Ce « client Sentry » (sentry.client.ts) n'est pas le SDK Sentry : il garde en mémoire les 20 derniers rapports d'erreur et n'envoie rien à aucun serveur, même si EXPO_PUBLIC_SENTRY_DSN est renseigné.

flowchart TD
  A["App.tsx : useFonts Inter"] --> R["Provider Redux"]
  R --> S["SafeAreaProvider"]
  S --> T["ThemeProvider"]
  T --> SH["AppShell : StatusBar"]
  SH --> RN["RootNavigator"]
  RN -->|"non connecté"| AU["AuthStack"]
  RN -->|"connecté"| MT["MainTabs et écrans empilés"]
  RN --> BS["Fenêtres globales ResultDialog"]

#Configuration

mobile-app/.env.example liste quatre variables. Expo intègre au bundle toute variable préfixée EXPO_PUBLIC_ au moment du démarrage de Metro ou du build.

Variable Valeur d'exemple Lue par
EXPO_PUBLIC_API_URL http://localhost:2053/api api.client.ts, donc baseApi
EXPO_PUBLIC_WS_URL http://localhost:2053 socket.client.ts
EXPO_PUBLIC_SENTRY_DSN vide sentry.client.ts, qui ne l'utilise que pour écrire une trace locale
EXPO_PUBLIC_WEB3AUTH_CLIENT_ID blocklucky-etherbay-client aucun fichier : vestige d'une intégration Web3Auth abandonnée

Trois autres variables sont lues par SocialAuthButtons.tsx sans figurer dans .env.example :

Variable Rôle
EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID Identifiant client OAuth Google utilisé sur iOS
EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID Identifiant client OAuth Google utilisé sur Android
EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID Identifiant client OAuth Google utilisé sur la cible web

Sans la variable de la plateforme courante, le bouton « Continuer avec Google » reste affiché mais désactivé, avec le message « Connexion Google non configurée sur cette application. ». Les identifiants doivent aussi figurer dans GOOGLE_CLIENT_IDS côté backend (voir Authentification et stockage sécurisé).

Important

localhost désigne le téléphone lui-même. Sur un appareil physique ou un émulateur Android, l'URL doit pointer vers l'adresse IP de la machine qui fait tourner le backend. La procédure est dans Tester sur un téléphone.

L'ancien README mentionne EXPO_PUBLIC_CHAIN_ID=11155111 : aucune ligne du code ne lit cette variable.

#Code mort à connaître

Le hook useGaslessWeb3.ts, qui présentait les achats comme sponsorisés par la plateforme, et le composant WalletConnectButton.tsx, qui invitait à « connecter » un portefeuille externe, ont été supprimés. La refonte de l'interface a aussi supprimé LoginScreen.tsx, SettingsStack.tsx et les composants ChatBox, CountdownTimer, LeaderboardList, POAPBadge, RouletteAnimation, TicketCard et WinnerClaimCard. Les citoyens ne connectent pas de portefeuille externe.

Il reste du code sans appelant :

Élément Situation
IntegratedWalletCard, IntegratedWalletButton Plus aucun écran ne les importe ; ExplorerLink n'est plus utilisé que par IntegratedWalletCard
