Licences

Cette page recense la licence du code de BlockLucky lui-même, puis celles des dépendances principales, des polices, de la bibliothèque embarquée et des photographies. Les versions et licences des dépendances ont été relevées dans les fichiers package.json des paquets installés (node_modules). La liste n'est pas exhaustive pour les dépendances transitives ; un inventaire complet demande un outil dédié (voir Produire un inventaire complet). Elle ne constitue pas un avis juridique.

#Licence du dépôt

Attention

Le dépôt ne contient aucun fichier LICENSE à sa racine ni dans ses sous-projets. Sans licence explicite, le code est par défaut protégé par le droit d'auteur : nul ne peut le réutiliser, le modifier ni le redistribuer sans autorisation des auteurs. Les mentions éparses ci-dessous ne remplacent pas un choix de licence global.

Emplacement Mention Commentaire
backend/package.json "license": "ISC" Valeur par défaut écrite par npm init, probablement non choisie ; contradictoire avec l'absence de fichier de licence
frontend-web/package.json, mobile-app/package.json, smart-contract/package.json, frontend-office-tourisme/package.json, documentation-officielle/package.json "private": true, pas de champ license private empêche seulement la publication sur npm
smart-contract/contracts/BlockLucky.sol, smart-contract/contracts/BlockLuckyPOAP.sol et les deux contrats de test // SPDX-License-Identifier: MIT Le code source vérifié sur Etherscan sera affiché sous cette mention

Le choix d'une licence revient aux auteurs et, le cas échéant, à l'école et à la Ville, selon les règles de propriété intellectuelle applicables à un projet pédagogique. Il est repris dans Points à valider. Un choix cohérent avec les mentions existantes serait une licence MIT pour l'ensemble, avec un fichier LICENSE à la racine et le champ license harmonisé dans chaque package.json.

À savoir

Le paquet @chainlink/contracts est publié sous la Business Source License 1.1, qui restreint certains usages en production. Les fichiers que BlockLucky compile portent néanmoins tous un en-tête MIT, relevé dans les sources embarquées par le compilateur (artifacts/build-info). Le bytecode déployé ne contient donc que du code sous licence MIT. Cette lecture fichier par fichier est à confirmer par un juriste avant une exploitation commerciale.

#Compatibilité

Les licences relevées sont toutes permissives (MIT, MIT-0, ISC, BSD, Apache-2.0) ou propres aux polices (OFL). Aucune licence à réciprocité forte (GPL, AGPL) n'a été repérée parmi les dépendances directes. Les obligations à respecter lors d'une distribution sont :

Licence Obligation principale
MIT, ISC, BSD Conserver la mention de droit d'auteur et le texte de la licence
Apache-2.0 Idem, plus le fichier NOTICE s'il existe et la mention des modifications
OFL 1.1 Distribuer le texte de la licence avec la police ; ne pas vendre la police seule
MIT-0 Aucune

Les images Docker et les bundles produits par Next.js et Expo incluent ces dépendances : leurs mentions doivent rester accessibles (fichiers de licence conservés dans node_modules des images, ou page de mentions dans l'application).

#Produire un inventaire complet

Pour un inventaire exhaustif, dépendances transitives comprises, lancer depuis chaque sous-projet un outil comme license-checker :

Terminal
npx --yes license-checker --production --summary

Cet outil n'est pas une dépendance du dépôt ; npx le télécharge à la volée. Un rapport par projet, joint à chaque version, permettrait de suivre l'apparition d'une licence incompatible. Voir aussi Dépendances.
